# Which qlean C functions Rel reaches

Computed, not read off names. Two reachability walks, then a C call graph over the entries they name:

- Lean side: `/data/tmp/relc-audit/Reach.lean` (`lake env lean --run`, qlean plugins loaded) imports the `LeetQ.Run`
  modules and `LeetQ.Rel.Lang.EmitC`, and walks the constant closure (types, values, `implemented_by`) until an
  `@[extern]` constant, read with `Lean.getExternNameFor`.
- C side: `/data/tmp/relc-audit/graph.py` dumps `clang -Xclang -ast-dump=json` of every `c/*.c` with the lakefile
  flags (`elementwise.c` three times, `-DEW_PART=1..3`; `scan.c` with `recurrenceFlags`), takes each function
  definition's line span, and follows `DeclRefExpr` edges from the entry symbols. No regex over C source.

## The two columns

| column | roots                                                                 | closure  | `qlean_` symbols |
|--------|-----------------------------------------------------------------------|----------|------------------|
| (a)    | all 5979 declarations of the 18 `LeetQ.Run.*` modules (interpreted)   | 20499    | 77               |
| (b)    | `LeetQ.Rel.Lang.Plan.abi` (the native ABI table, `kernel%` entries)   | 519      | 3                |

- (a) is the runtime `rel_program` uses at elaboration time and the interpreter path; it over-approximates any one
  program, because every `Run` declaration is a root.
- (b) is what the native path can call: `qlean_own_write`, `qlean_sort_group_ids`, `qlean_sort_id_groups`
  (plus `lean_usize_dec_eq`, a Lean runtime inline, not qlean). `Plan.lean` also emits only those three strings.
- (b) is not a subset of (a): `qlean_own_write` is reached only through `EmitC`'s `output`.

## Vector intrinsics

A function counts if its body references an `_mm*` or `__builtin_ia32*` function (the build is `-march=native`;
this host has AVX-512, so those are the AVX-512 forms, `__m512`/`__m256` types).

| function         | file          | line | span | on (b)? |
|------------------|---------------|-----:|-----:|---------|

  `guid_words` use only `__builtin_popcountll` / `__builtin_bswap64`, which are not AVX.

## own.c, zip.c, ALP, FoR
| question                    | answer                                                                           |
|-----------------------------|----------------------------------------------------------------------------------|
| `exc_ok` (`own.c:192`)      | not reached by (a) or (b); its callers (`own.c:301,312`) precede `own_map`       |
| `own_map`, `file_replace`   | not reached; (b) uses `qlean_own_write` only (`own.c:147`, 34 + 43 helper lines) |
| anything in `zip.c`         | not reached: `qlean_zip_{head,size,bytes,parts}` have no Lean caller in Rel      |
| ALP (`alp_*`)               | reached by (a): `coc.c`, `coc.h`, `structural.c`; `keys_blk_alp` also on (b)     |
| FoR (`*_foR`, `cap_for`)    | reached by (a) via sort/structural entries; `keys_blk_foR`, `range_foR` on (b)   |
| exception side (`coc_exc`)  | reached by (a) from `coc.h`; `coc_exc` is also on (b)                            |

- ALP/FoR are on Rel's path through `coc.c`, `coc.h` and the sort/structural entries; the port's own.c and zip.c
  pieces are not: only `qlean_own_write` of `own.c` is.
- ALP unreached entries: `alp_{min,max,sum_*,mask_lt}`, `mwin_alp`, `scan_alp`.
